### <a name=""></a>**Название задачи: Передача актуальных депозитных ставок в кол-центр**
### <a name=""></a>**Автор: Дмитрий Варгин (Исполнитель)**
### <a name=""></a>**Дата: 28.10.2025**

### <a name=""></a>**Функциональные требования**

| **№** | **Действующие лица или системы**                                   | **Use Case**                               | **Описание**                                                                                                                                                                                                                                       |
| :--: |:-------------------------------------------------------------------|:-------------------------------------------|:---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 1 | Сотрудник кол-центра, система кол-центра                           | Просмотр актуальных ставок (внутренний КЦ) | 1) Клиент звонит в кол-центр с вопросом о ставках.<br>2) Сотрудник кол-центра запрашивает текущие ставки.<br>3) Система кол-центра запрашивает данные у Сервиса ставок по REST API (HTTPS).<br>4) Система кол-центра отображает ставки сотруднику. |
| 2 | Сервис ставок                                                      | Формирование файла ставок                  | 1) Сервис ставок получает данные ставок из АБС (АБС — источник правды) и создает файл XLS/XLSX.                                                                                                                                                    |
| 3 | Сервис ставок, партнерский кол-центр                               | Выгрузка ставок для партнера               | 1) Сервис ставок передает сформированный файл в партнёрский кол-центр по SFTP (SSH).                                                                                                                                                               |
| 4 | Сотрудник партнерского кол-центра, система партнерского кол-центра | Использование ставок партнером             | 1) Система партнерского кол-центра забирает файл по SFTP и использует ставки для консультаций клиента.                                                                                                                                             |

### <a name=""></a>**Нефункциональные требования (измеримые)**

| **№** | **Требование** |
| :--: | :-- |
| 1 | Интеграция: внутренний кол-центр использует REST API (HTTPS) к Сервису ставок; SFTP используется исключительно для внешнего партнёрского кол-центра. |
| 2 | Производительность (API): время ответа на запрос ставок — P95 ≤ 200 мс, P99 ≤ 400 мс при нагрузке до 20 RPS. |
| 3 | Доступность (API): SLO 99.9% в месяц (допустимый простой ≈ 43.8 мин/мес). |
| 4 | DR (API): RTO ≤ 1 час, RPO ≤ 5 минут. |
| 5 | Безопасность (API): HTTPS/TLS 1.2+, аутентификация (например, JWT), корреляция запросов (traceId). |
| 6 | Доставляемость (SFTP): доступность канала 99.5%/мес; публикация файла при изменении ставок и гарантированно не реже 1 раза в сутки; задержка генерации файла ≤ 5 минут. |
| 7 | Ограничения по файлам (SFTP): максимальный размер ≤ 5 МБ; формат XLS/XLSX; кодировка UTF-8. |
| 8 | DR (SFTP): RTO ≤ 4 часа, RPO ≤ 1 час. |
| 9 | Актуальность данных: для внутреннего КЦ — «почти в реальном времени»: Сервис ставок синхронизируется с АБС по расписанию (не реже 1 раза/сутки) + ручной триггер; кеш Redis TTL 15 мин и политика stale-while-revalidate до 5 мин. |

### <a name=""></a>**Решение**

**Логика выбора решения:**

1. Единый источник правды: ставки хранятся и администрируются в АБС; Сервис ставок — витрина и точка интеграции (REST для внутреннего КЦ, SFTP — только для партнёра).
2. Интеграция с внутренним кол-центром: Система кол-центра вызывает Сервис ставок по REST API (HTTPS) — обеспечивает актуальность и низкие задержки.
3. Интеграция с партнёрским кол-центром: Сервис ставок формирует и передаёт файл по SFTP (SSH) — обеспечивает защищённую файловую доставку.

**Основные компоненты:**

- Сервис ставок: предоставляет ставки по REST API внутреннему КЦ; формирует и публикует файл для партнёра по SFTP; синхронизируется с АБС по расписанию; ведёт кеш для ускорения чтений.
- Система кол-центра: доработка для интеграции по REST API к Сервису ставок.
- АБС: источник правды по ставкам.

### <a name=""></a>**Альтернативы**

1. Система кол-центра запрашивает данные напрямую из АБС (отклонено: риск нагрузки и отсутствие витрины/кеша).
2. Партнёрская система кол-центра запрашивает файл со ставками из АБС (отклонено: утяжеляет АБС интеграциями; витрина должна быть в Сервисе ставок).

### <a name=""></a>**Недостатки, ограничения, риски**

**Недостатки выбранного решения:**

1. Увеличение ответственности Сервиса ставок (витрина, кеш, SFTP-выгрузки).
2. Зависимость кол-центров от Сервиса ставок — точка отказа (требует выполнения SLO 99.9% и DR-мер).

**Ограничения:**

- Партнёрский кол-центр может принимать данные только через SFTP.
