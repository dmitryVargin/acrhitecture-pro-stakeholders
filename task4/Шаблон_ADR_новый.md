### <a name=""></a>**Нефункциональные требования**

|**№**| **Требование**                                                                                                                                                                           |
| :-: |:-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|1| Интеграция ,Для обмена данными Системе внутреннего контактного центра требуется REST API, в то время как внешняя партнерская система использует метод файлового обмена.                  |
|2| Производительность,Время ответа Службы предоставления тарифов на запрос, исходящий от Системы контактного центра, не должно превышать 200 миллисекунд.                                   |
|3| Масштабируемость ,Служба предоставления тарифов и Системы контактного центра должны быть готовы к горизонтальному масштабированию для обработки ожидаемого роста нагрузки.               |                                                                                                                                         |
|4| Безопасность ,Передача файла с тарифами во внешнюю партнерскую систему по обслуживанию клиентов должна быть выполнена по защищенному протоколу передачи файлов.                          |
|4| Актуальность данных ,Актуальные тарифы должны быть доступны в системе колл-центра в режиме, почтт к реальному времени. Для внешней партнерской системы допускается минимальная задержка. |

### <a name=""></a>**Решение**

**Логика выбора решения:**

1. Единый источник правды: Используется сервис ставок для всех запросов ставок. АБС не задействован 
2. Интеграция с внутренним и партнерским колл-центром: Интеграция сервиса ставок и кол-центра по REST API. Обеспечивается актуальность и высокая скорость передачи.
3. Интеграция с партнерским центром: Интеграция сервиса ставок и партнерского кол-центра по SFTP. Обеспечивается безопасность данных.

Основные компоненты:

Сервис ставок: Предоставляет ставки через REST API и файлы через SFTP.
Система кол-центра: Доработка для интеграции с сервисом ставок.


### <a name=""></a>**Альтернативы**

1.  Система кол-центра запрашивает данные из АБС.
2.  Партнерская система кол-центра запрашивает файл со ставками из АБС.


**Недостатки, ограничения, риски**

Недостатки выбранного решения:

1. Увеличение сложности сервиса ставок
2. Зависимость кол-центров от сервиса ставок - точка отказа

Ограничения:
Партнёрский кол-центр может принимать данные только через SFTP
